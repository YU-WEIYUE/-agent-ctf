# Agent CTF Competition Playbook

本手册供授权 Jeopardy CTF 中的主调度 Agent 和解题 Agent 复用。它来自一次 48 小时 rCTF 实战：最终 42/68 题、2461 分、12 类全覆盖。数字只描述该次赛事，不代表模型通用能力。

## 1. 先打通得分闭环

开赛前必须真实跑通：

```text
doctor -> self-test -> platform me -> platform list -> pull -> submit probe
```

`HTTP 200`、命令退出 0、发现 flag 形状字符串都不等于成功。只认平台接受回执或赛事规定的独立验证器。平台凭据只能在宿主侧，题目执行容器保持断网、非 root、只读根和最小权限。

开赛前要记录：平台类型、认证方式、附件哈希口径、提交返回值、实例启动/续期/释放方法、并发实例上限、错误提交惩罚、动态计分规则和比赛截止时间。

## 2. 主调度 Agent 的职责

主调度 Agent 不长期下场挖单题，只负责：

1. 建立题目表：类别、当前分值、solve 数、是否需实例、负责人、开始时间、状态。
2. 保证一题一个负责人；只有明确拆分静态分析/利用开发时才允许双人协作。
3. 统一管理稀缺实例和查询配额，释放已解出、已放弃或失联任务的资源。
4. 按信息价值补位：通常先参考 solve 数，再结合分值、类别能力和已有情报。
5. 每 15 分钟检查实例，每小时核平台成绩，每 30–60 分钟检查长任务是否还有新增信息。
6. 只从平台成绩接口确认得分，不接受“已经提交”“应该对了”等口头状态。

动态计分赛事中，高分题越早完成越有价值；但临近结束时，solve 数高的题通常比少人解出的高分题更有确定性。最后一小时应收敛到高 solve 数题和已有进展，不再盲开长任务。

## 3. 固定委派卡

每次派题必须提供以下字段：

```text
题目：<name>（<category> / <points> / <solve_count> solves）
题目 ID：<id>
唯一负责人：<agent>
截止时间：<absolute timestamp and timezone>
已确证事实：<addresses/constants/protocol/test cases>
已否证路径：<do not repeat>
当前卡点：<one sentence>
下一步动作：<copyable command or concrete experiment>
错误提交预算：<= 3；不确定不交
实例规则：<start/renew/release/concurrency/query budget>
已知诱饵：<do-not-submit list>
交接产物：HANDOFF.md + scripts/dumps paths
```

时间只写绝对截止时间与时区。任何“还剩多久”都应由当前时间计算，不能凭消息节奏估计。

## 4. 单题 Agent 的证据纪律

单题 Agent 必须区分：

- 已确证：有程序输出、反汇编地址、协议响应、哈希或可重复测试。
- 候选：推断合理但尚未被验证。
- 已否证：具体输入、命令和输出已经反驳。
- 未验证：缺实例、缺依赖、超时或只完成静态猜测。

发现 flag 形状字符串后，先检查它是否位于测试代码、错误分支、示例配置或诱饵文本，再决定是否提交。错误提交预算是硬上限，不因临近结束而放宽。

30–60 分钟没有新增可改变决策的信息时，必须换策略或收口。停止不是只写“没解出”，而是生成可接力的交接。

## 5. HANDOFF.md 的五个必填项

```text
1. 已确证事实：带地址、常量、哈希、请求响应或校验用例。
2. 已否证路径：写明为什么失败，避免下一棒重复。
3. 精确卡点：一句话定位未知量。
4. 下一步命令：可以直接复制执行。
5. 产物路径：脚本、dump、日志、反编译结果和输入哈希。
```

新 Agent 先复验一条关键事实，再沿交接继续。不得只凭上一位 Agent 的结论接着猜。

## 6. 实例与并发

- 一题一负责人，避免互抢查询配额或覆盖状态。
- 实例池由主调度 Agent 独占管理；子 Agent 申请、主 Agent 分配。
- 启动实例后轮询端点，空数组不是失败；记录启动、续期和到期时间。
- 已解出或放弃后立即释放；不要让后台续期脚本长期占用配额。
- 查询预算也是共享资源。双 Agent 协作时必须预先划分不同目标，不能同时对同一 oracle 穷举。

## 7. 赛中节拍

每小时：

1. 从平台接口刷新分数和 solve 列表。
2. 更新题目表并按 solve 数、已有进展和资源成本补位。
3. 清理闲置实例和失联后台进程。
4. 对长任务执行继续/转向/停止判断。
5. 确认每个停止任务已经写出 HANDOFF.md。

最后一小时：

- 优先高 solve 数和已有中间结果的题。
- 不再启动预计无法在截止前验证的新长任务。
- 同步生成成绩表、未解卡点和代表性解法索引。

收尾十分钟：

- 刷新最终成绩并保存时间戳。
- 释放全部实例，停止后台计算，检查容器和进程。
- 保存输入哈希、脚本、日志和平台回执；凭据与会话文件单独留在忽略目录。

## 8. 公开发布闸门

公开仓库只允许：原创代码、许可证允许的第三方代码、自建样例、测试、脱敏方法文档和不含账户身份的聚合成绩。

禁止公开：平台 token/cookie、实例端点、完整 flag、个人绝对路径、平台原始回执、未获授权的赛题附件、内存镜像/PCAP、现场工作目录和包含第三方个人信息的 OSINT 资料。

发布前至少执行：

```text
git status --short
git diff --cached --name-only
secret scanner over staged files
ruff check + format check + mypy + pytest
```

审计对象必须是“将要提交的文件”，不能用 `.gitignore` 代替审计。
